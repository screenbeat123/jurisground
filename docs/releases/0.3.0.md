# JurisGround 0.3.0

Numbers are now checked against the source fragment that actually matched the quote. This release also adds optional checks for common Polish statutory citations.

- Inspect the matched fragment's numbers through `evidence_numbers`.
- Keep complete numeric tokens: a quote containing `100` cannot use part of `-100` or `1000` as evidence.
- Find alternative OCR evidence when a closer text match contains the wrong amount, and preserve source offsets when normalizing Unicode.
- Reject unsupported citation ranges and malformed unit order without turning them into a shorter reference.
- Check short claims too; blank or unusable claims remain `unverified`.
- Read UTF-8 BOM input files, report invalid CLI input without tracebacks, and preserve Unicode JSON output on Windows consoles.

The included [synthetic demo](../../examples/README.md) shows a passing claim, a changed amount, and a changed legal citation. It uses invented development data, not a production case.

## Migrating from 0.2.0

Remove `Policy.min_content_stems_for_support`. Only `quote_threshold`, `ocr_quote_threshold`, and `min_claim_support` accept positional arguments; name all later settings.

The 0.2.0 `ClaimResult` constructor is preserved: its fifteenth positional argument is still `findings`. Pass `claim_legal_citation`, `evidence_legal_citation`, and `evidence_numbers` by name. Callers using the temporary 17-argument layout from unreleased development must move the two citation arguments to named fields.

The CLI now rejects invalid field types instead of coercing them, along with unknown policy keys and nonfinite numbers. Non-ASCII output uses JSON `\uXXXX` escapes; parsing the JSON restores the original Unicode text.

A passing result means the configured mechanical checks passed. It does not establish factual or legal correctness; lexical overlap can still miss negation and changes in meaning.
